## 实测结果

- 第一次使用菜单选择全部群组：三个群各选中 2 条页面消息；前两个群新下载 0、失败 0，第三个群新下载 20、失败 0。下载汇总为 20 个新附件、失败 0；菜单随后再次等待输入，自动输入耗尽而使 BAT 退出码为 1。
- 第二次通过 BAT 直接传入配置中的三个群组链接，同样使用 `--limit 2`：三个群处理与下载汇总相同，BAT 退出码 0。
- 两次下载的媒体 ID 集合均为 20 个且交集为 0；第二批 ID 更大，是新的消息，不是重复下载。今天写入的 40 个媒体文件均非空，SHA-256 可计算且 40 个摘要互不相同；程序报告编组核对并移入成品目录，已选原消息均有扫描和处理记录。
- 日志保存在 Git 忽略的 `~temp/three-group-bat-limit2.log` 和 `~temp/three-group-bat-direct-limit2.log`，含真实群组信息，仅供本机排查。
- 未验证：完整群组历史、先前失败附件是否全部恢复，以及更大文件的续传路径。此任务没有修改下载程序。
