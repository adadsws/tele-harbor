# 暂存残留只读诊断

历史阶段记录：以下行为、数量和结论对应当时版本与样本；不作为当前模式说明或本次重新实测的结果。当前规则见 [项目规范](../AGENT_CONTEXT.md)，当前状态见 [遗留索引](../plans/2026-11-08-remaining-verification.md)。

## 范围与方法

2026-11-11 按用户要求检查“一个群已到最早消息但暂存仍有文件”。依据本机配置读取实际目录，以扫描记录、文件元数据、发布条件和当日日志交叉核对；不打开媒体或消息原文，不重试已停止专项实测的原件，不修改下载数据。本次仅诊断，不实施代码修复或数据整理。

## 结果

- 目标群扫描记录的 `history_complete=True`，覆盖 2026-08-23 至 2026-11-07。此标记说明已确认可访问历史最早端，不代表全部附件下载成功。
- 记录中共 6,605 个媒体附件，6,604 个结果为 `skipped`，1 个为 `failed`；另有 46 条 `saved_content`。这些是当前记录状态，不代替本轮全量文件哈希验收。
- 暂存中的大头像段预期 1,023 个媒体附件，实际索引有 1,022 个，唯一缺件为预期大小 19,266,574 字节的视频。对应失败记录及当日日志均为 Telegram `500 UNKNOWN`，且该件已在本机实测排除清单登记停止专项追查。本轮没有请求原件字节。整段及关联分量未齐，发布条件拒绝，保留暂存符合现行规则。
- 大头像段所属关联目录共 1,061 个文件，其中包含上述已下载媒体、消息内容与辅助记录及失败说明；不能把全部残留都计为未下载附件。
- 另一关联目录仅剩 116 字节的 `关联清单.json`，成品中已有同路径清单和头像段；两份清单逐字节一致。这是独立的发布收尾遗漏，不是又一个缺失附件。
- 当日对应运行最终记录 `existing=6604 failed=1`，退出码为 1、原因为 `incomplete`，并未声明全群附件成功。

## 收尾遗漏的依据

`src/telegg/browser.py` 的 `ensure_publish_association` 只在成品清单不存在时移入暂存清单；目标清单已存在时不处理暂存副本。`publish_ready_staged_groups` 移走头像段后，`archive_empty_relocated_folders` 只归档空目录，因此含这份 JSON 的上层关联目录会留下。

后续修复应核对成品关联清单与当前引用关系，再安全归档已无业务文件的暂存辅助副本；遇到内容不一致或未完成成员必须保留并报错，不能直接删除或放宽整段发布条件。问题移交 [遗留索引](../plans/2026-11-08-remaining-verification.md)。

## 证据与限制

本机证据为配置指向的扫描记录、暂存/成品目录和 `~temp/logs/telegg-20261111-122346-823433.log`。精确群号、消息号及路径保留在这些本机原始证据中，本文不复制隐私标识。

未做全量媒体 SHA-256、重新在线核对最早端或服务端错误根因鉴定；没有运行 BAT、修改完成状态或迁移文件。其他两群暂存亦有未处理消息，不能由目标群最早端状态推断为已完成。另观察到一个满足当前只读发布条件的段仍在另一群暂存，其运行是否到达正常收尾尚未核对，本次不推断具体原因。
