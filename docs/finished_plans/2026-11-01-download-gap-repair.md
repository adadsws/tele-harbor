# 下载缺口修复与验收

## 需求和现状

- 用户要求修复所有已发现的下载问题，并实际补下、复核。
- 用户补充：`X:\TelegramData` 下使用 `downloading/` 与 `downloaded/`；只有编组全部文件确认齐全后才进入 `downloaded/`。
- 用户后续确认：扫描追到最早端且只领先下载一组；补下载验收限于任务开始前已有扫描记录。更早历史新发现的附件仍纳入采集审计，缺口单列。
- 现有记录覆盖 642 个可下载附件，磁盘有 157 个，485 个缺失。其中 96 个有“无法定位原消息”失败记录，369 个未处理，10 个标为已跳过但磁盘缺失，10 个尚未识别。后两群扫描记录尚未标记完整历史，最终数字需以重新扫描为准。

## 样例与验收

| 输入或状态 | 预期行为 | 预期输出 |
|---|---|---|
| 旧消息附件定位失败 | 能重新定位原消息并下载，失败记录更新 | 文件在 `X:\TelegramData\downloaded` 且大小一致 |
| 已跳过但文件不存在 | 重新下载或明确报错，不把旧状态当作已完成 | 结果记录与磁盘一致 |
| 未处理或未识别附件 | 全量运行处理，保持可续传 | 已记录附件有成品或明确不可处理原因 |
| 重复执行 | 不覆盖已有成品，不重复下载 | 已有数增加，新下载 0 |
