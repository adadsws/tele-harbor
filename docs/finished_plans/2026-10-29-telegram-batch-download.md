## 需求与边界

- 仅通过 Windows BAT/CMD 启动，不提供 WebUI。
- 下载账号有权访问的 Telegram 群组历史消息附件，覆盖照片、视频、文档、音频、语音、贴纸等 Telegram 消息媒体。
- 按消息从旧到新排序；没有正文的媒体消息暂存，遇到下一条有正文的消息时，将暂存消息与该消息的全部媒体放入以该有正文消息日期及文字命名的目录。
- 支持 Web K 地址中的三个群组：`-1000000005`、`-1000000003`、`-1000000004`。
- 对开启内容保护的群组尝试账号可访问的媒体下载；下载失败必须保留错误并诚实报告，不能假定 Telegram 一定允许取回。
- 2026-10-30 三群受限媒体调试：核对目前三个群组内样本消息的内容保护标记与普通下载控件，再用独立输出目录做有界真实下载。失败时修复通用路径并复测；普通媒体成功不代表受限媒体通过。
- 调试发现同一页面依次访问群 1、群 2 时，Telegram Web K 可能保持旧群组 hash，`open_group` 超时；需在单标签内完整重载后继续，验证“下载全部群组”不会停在第一群。
- 断点重跑不覆盖完整文件；错误文件保留临时文件以便诊断。用户凭据和会话不写进 Git。
- 2026-10-29 补充：含多个消息的归组目录下，每条消息各有以消息本身发送时间（精确到秒）命名的子目录，媒体放入对应消息子目录；同秒消息以 ID 后缀区分。单条消息的归组目录保持原有直接存放文件的结构。
- 2026-10-29 路线变更：用户没有 API 凭据，改为纯 BAT/CMD + 脚本操控可见 Chrome 中的 Telegram Web；不使用插件或 AI 作为程序运行依赖。首次登录在独立浏览器窗口由用户完成。

- 2026-10-30 最新端即时下载优化：在本轮首条有文字消息出现之前，扫描到的无文字消息必定属于 `未归组/`，可逐条立即入队下载核验；若 `--limit N` 全部选中的都是这种尾部消息，处理到 N 条即可停止，无需额外扫描文字边界。有文字锚点的最后一批仍须读到更早边界才能确定多消息目录。
