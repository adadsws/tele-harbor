# 项目结构与约定

本文件记录当前架构和验收标准；代理执行规则见 [项目代理规则](AGENTS.md)，用户操作见 [使用说明](../README.md)。

- `download.bat` 启动 `src/telegg/__main__.py`，提供群组菜单或直接链接输入。
- `config/config.local.json` 保存本机群组号和运行数据路径，Git 忽略；`config/config.example.json` 提供不含真实标识的配置结构。启动时先打开 Chrome、等 Telegram 会话入口可见并报告“环境就绪”，随后依次打开已配置群组读取当前标题，再显示“群名 [ID]”菜单。名称只在本次内存中使用，不写回配置；读不到时回退显示 ID。菜单退出会关闭本次 Chrome。
- `browser.py` 使用一个 Chrome 页面从新到旧扫描；确认下一编组后处理上一编组，最多保留一个已确认待处理编组，下载导致跳转时恢复旧端位置。不使用媒体队列或下载批次。Web K 虚拟列表停住后按当前最旧原消息 ID 从已登录会话的服务器历史接口分页读取，只有空页确认最早端；相册泡泡的扫描交接取其中最小原消息 ID。
- 从 Telegram 首页或其他群组打开目标群时 Web K 可能保留空聊天或旧 hash；`open_group` 先导航 `about:blank` 卸载旧页面，再打开目标群组。下载使用 Web K 已登录会话的 `apiFileManager.requestFilePart`，不经过浏览器整文件下载事件。
- `layout.py` 按 Telegram 原消息正文与时间计算目录；无正文消息归于下一条有正文消息，最新端剩余消息归于 `未归组/`。
- `scan_record.py` 在 `X:\TelegramData\state\scan-records/` 保存已扫描消息、附件 ID 和历史最早端标记，用于增量扫描与失败续跑；`--limit` 不标记完整历史。
- `content_types.py` 按 Telegram 原消息 `media._` 和文档属性分类；`browser.py` 将分类与页面可操作附件 ID 逐项核对。新扫描遇到未知媒体类型或新附件框时记录失败，避免静默按无附件处理。旧扫描记录缺少分类字段时仍可加载。
- `content_archive.py` 为正式下载处理过的每条原消息在 `X:\TelegramData\state\messages/<群目录>/.messages/` 写入带哈希的 JSON 内容文件；纯文字与可序列化的非文件内容也保存，内容变化不覆盖旧版。无法完整保存的类型在分类核验时失败，等待针对真实页面实现。
- 已有文件按媒体 ID 核对与迁移；重复 ID 多文件报错且不覆盖。`resumable.py` 在输出根目录同级持久保存单文件分片和追加提交日志，每次先 fsync 数据、再 fsync 提交记录；重启逐块核验哈希并从提交偏移继续。完整文件再次核验大小和 SHA-256 后同卷原子重命名入输出目录，暂存文件不在输出根目录内。旧版 256 KiB 断点仍可读，新断点用 1 MiB 分片。
- `progress.py` 格式化编组文件和单文件字节进度条；`browser.py` 根据已提交分片计算速度并显示续传起点。编组文件总进度表示已处理数量（含失败），最终失败数另行报告。
- `tests/` 包含归组、扫描记录、单页处理顺序与浏览器下载样例。

## 评测集与验收标准

来源分为真实需求和预测场景。离线样例由 `tests/` 中对应测试验证；真实 Telegram 样例必须另记录实际运行证据，不能以离线测试代替。过程证据包括命令、退出码、扫描记录、分片提交日志和成品大小/哈希核对。

| 来源 | 输入及前置状态 | 预期行为（过程） | 预期输出（结果） |
|---|---|---|---|
| 真实需求：重复运行 | 已有完整媒体，执行有界下载 | 按媒体 ID 核对已有文件，不覆盖、不重复下载 | 完整文件保持一致，失败数为 0 |
| 真实需求：中断续传 | 已有已提交分片后重启 | 逐块核验提交日志和哈希，从已核验偏移继续；整组核齐后发布 | 成品大小与 SHA-256 正确，未齐组不进入 `downloaded` |
| 真实反馈：虚拟列表停住 | 旧端页面不再加载，执行 `--dry-run` | 从服务器历史接口继续按原消息 ID 递减扫描，仅空页确认最早端 | 扫描记录无漏项；无法确认时失败且不写完成标记 |
| 预测：未知媒体 | 页面出现未支持的媒体类型或附件框 | 保留消息 ID 和失败原因，不按无附件跳过 | 退出码非零，扫描记录可定位失败项 |
| 预测：登录或网络失败 | 无有效会话或请求连续超时 | 显示错误并保留续传状态，不发布未齐组 | 可重新运行，原有成品不受影响 |
| 真实反馈：正文编辑 | 同一长正文消息的前 20 字不变，完整正文发生变化 | 同编号全文变化时将原文件改名为 `完整文字.v1.txt`，新版写入 `v2`，后续递增；附件按消息编号和附件位置判定版本 | 重跑复用最新版本，旧版不覆盖，位置不明时报错 |
| 预测：附件被替换 | 同一消息编号及附件位置的媒体身份或大小变化，已有文件和分片身份记录 | 旧附件改为 `.v1`，新附件下载并核验后保存为 `.v2`；再次运行核对当前身份 | 两版均保留，最新版本复用；附件位置变化时安全报错 |
| 真实需求：CMD 日期进度 | 使用 BAT 对有界群组样本下载 | 扫描日期与文件处理日期分别显示；技术 ID 和诊断细节留在本机日志 | 显示本次处理到的日期、文件计数和退出结果，不误称完整历史 |

交付时逐行核对实际输入、过程和结果，并在所属任务 Plan 中记录证据与未验证项。离线测试在项目根目录设置 `PYTHONPATH=src` 后，用 `.venv-browser/Scripts/python.exe -m unittest discover -s tests -p 'test_*.py' -q` 运行；真实入口为 `download.bat`，需选取有界参数及当前有效账号会话。
