# 三模式共享检查与写入边界

三种模式应分别控制“是否保存新内容”“是否检查已有文件”“何时允许修正”。后两种模式复用一个检查器；不把检查模式实现成下载流程加静默开关，以免写入新状态。已完成记录缺件延迟到最终确认，未完成资源仍属于正常下载。

确认必须在所有所选群组完成后集中执行；默认拒绝、EOF 和多群只问一次均须覆盖。启动前已存在的辅助残留也要保护，避免旧自动收尾提前归档。确认前后重新核对文件状态、扫描记录和目标是否出现，保留并发变化现场。

补缺只读原身份与验收摘要作为基线，以空本地索引、独立恢复目录从服务器下载，最终摘要一致才放回登记路径。错位副本归档不等于复用；合法连续版本链也不能因路径不同误报额外。

实际 BAT 验收应区分“检查通过且拒绝修改”与“已恢复完整”。人工清除完成记录形成的新内容样例只证明模式差异，不代替自然外部新增相册。阶段证据见 [验收记录](../finished_plans/2026-11-12-storage-review.md)。

Windows 证据路径统一使用 `as_posix()` 或按 `Path.parts` 判断归属。下载流程可正常更新扫描记录及指定分片区验收缓存，检查模式则要求这些状态也不变；不可仅凭后缀放过成品区用户文件。验收器有误时保留首次结果，用新副本重跑受影响组合，再显式合并并核对下载源码一致和跨批原件保护。独立复核还应避免结果总索引与单消息索引使用同名变量。实证见 [全模式记录](../finished_plans/2026-11-12-all-modes-live.md)。

小样本不能证明大目录吞吐。阶段提示应区分联合路径检查、结构与全量媒体哈希，文件内部必须有字节进度，并验证取消会停止后台读取。记录待读总字节和多种缓存条件下的耗时，不能把最后一条控制台提示当作现场栈；初次核验失败也不应在收尾再读取一遍。实证见 [大目录进度](../finished_plans/2026-11-12-review-progress.md)。
