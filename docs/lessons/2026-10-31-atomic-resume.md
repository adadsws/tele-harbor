# 原子续传复盘

## 项目专项复盘

- Web K 的 `apiFileManager.requestFilePart` 可沿用可见 Chrome 登录状态获取文档及照片分片；末段请求长度仍须按 Telegram 分片规则对齐，实际返回长度才是文件剩余字节。
- 将暂存放在输出目录同级，数据与提交日志分别 `fsync`，重启逐块核验后续传；完整文件才同卷重命名入库。
- 清理旧下载函数时误删相邻的扫描核验入口；随后用 BAT 下载和 `--audit-messages` 分别复核两个入口。

## 跨项目通用实践

- 中断测试须同时检查恢复偏移、最终产物和暂存状态；单看退出码不足以证明续传。
- 大块分片提升吞吐时，旧断点的块大小须由持久记录决定，不能直接以新默认值解释旧数据。
