# 复盘

## 项目专项

- Telegram Web K 链接的群组数字 ID 可以通过账号已加入的对话列表匹配，下载时须以该账号实际可访问性为准。
- 历史消息按旧到新遍历，能直接把连续无文字消息缓冲到下一条有文字消息；有界调试时先取最新 N 条再反转。
- 对多消息归组按每条消息的秒级时间建子目录，并以 ID 处理同秒冲突；单消息归组保持平铺，避免无关层级变化。
- Telegram Web 登录页也存在 `#column-left`，应以真正的对话列表判断登录完成；浏览器 Profile 独立保存且窗口保持可见。
- Telegram Web K 的相册子项在 `.album-item` 上带各自 `data-mid`；只读取外层气泡 ID 会漏掉相册中的其他文件。
- 页面上的多个媒体节点可能指向同一个 `data-mid`；入队时按媒体 ID 去重，避免反复下载同一大文件。
- Web K 某些气泡的 DOM 时间戳可与真实消息时间相差数秒；目录时间应优先使用消息元数据中的 `date`，否则重跑会在另一个秒级目录生成重复文件。
- 文档卡片中的文件名可能被渲染进 `.message` 节点；归组正文必须取消息元数据的 `message` 字段。元数据缺失时对媒体消息停止归组，避免把文件名误作说明；修正规则后按媒体 ID 迁移旧文件。
- 下载源与保存副本做大小及 SHA-256 核对后再改为正式文件；已有文件只能完成本地核对，日志状态要区分 `verified` 与 `existing_checked`。

## 跨项目通用实践

- Windows `.bat` 入口应使用 CRLF；用实际 `cmd /c` 运行验证，而非只做文本检查。
- Windows CMD 默认编码可能无法打印文件路径中的私用区字符；BAT 设置 `PYTHONIOENCODING=utf-8`，Python 入口也显式配置输出编码。
- 外部服务接口的单元测试只能验证本地逻辑，账号权限与服务端限制仍需真实环境验收。
