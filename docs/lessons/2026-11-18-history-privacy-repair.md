# 历史隐私修复边界

本项目的代理快照 ref 中有直接指向 tree 的记录，不能要求它们出现在 commit-map 中；先核对对象类型和隐私命中，保留无命中的树引用，再验证所有 ref。源码正文、测试及其他非目标历史文件逐一保持一致，只脱敏已确认的旧 README 编号。

Windows 多行回调参数会受启动器转义影响；使用仅含公开正则和审计对象 ID 的回调文件，避免把真实编号放入命令参数或日志。固定工具在 bare 镜像使用 partial/no-gc，不自动清理旧对象；验证后的独立对象库接入源工作区，旧 Git 元数据留作明确可恢复副本。

正常本机提交已恢复，源历史仍不直接发布，因为包含只允许本机保留的归档。公开副本继续沿既有公开 main 普通快进。人工恢复副本清理与平台缓存永久擦除是不同状态，详见 [修复计划](../plans/2026-11-18-history-privacy-repair.md)。
