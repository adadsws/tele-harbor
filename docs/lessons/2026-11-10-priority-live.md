# 五项优先实测复盘

- 只检查成品清单会漏掉暂存自动整理前的错误。关联预检同时覆盖成品和暂存，区别仅是暂存允许目标文件未齐；负例必须验证报错发生在文件和记录修改前。
- 完成标记不能只用于逐条跳过。最新页在线确认后，匹配当前元数据和附件的标记可支持直接定位端点；旧记录先在线补标记。快速信任范围及无法发现的旧区间修改需明确写入规范。
- 观察器和构造器本身也要验收：服务消息、DOM 时间偏移、界面未初始化、真实首个未完成资源与人为缺口不一致，都可能造成错误结论。保留失败现场，修正后只重跑受影响证据。
- 大量部分副本只验证快速信任和端点行为，不能拿来证明文件完整。已有媒体单独全量哈希，实际新下载单独核对分片及最终哈希，双模式计时使用相同下载初态。
- 自然外部新增缺条件时保持未验证；下载以前未覆盖的旧资源或制造缺件都不能替代自然新增。
- 网页 URL 参数与原生接口的消息号边界要分清，且应实测同文档和全新页面两种导航。简单按参数生成气泡的夹具会掩盖真实路由恢复旧状态的问题；先复现状态依赖失败，再验证产品卸载旧页后的恢复，并以真实目标进入视口收尾。
- 插件慢调用应拆步并给足工具时限；默认调用时限触发会话重置后出现的“调试器未连接”，不应反复要求用户重连来代替诊断。
