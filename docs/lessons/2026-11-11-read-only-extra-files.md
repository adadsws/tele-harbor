# 额外文件只读检查的边界

- 不用 `PartialFile.open()` 的默认写入方式做盘点：它可能在断电尾行场景归档并重写日志。额外项盘点子步骤只读取身份头、校验快照和文件元数据，不读取 `.part` 或媒体字节。当前逐文件/检查模式还会执行后续媒体 SHA-256 检查，需要读取已完成媒体；确认后可以修正，旧独立模式的“只读”不能用于概括整个当前流程，见 [现行规则](../AGENT_CONTEXT.md#缺失和额外检查及确认修正)。
- `.part` 入库后，数字命名的提交日志与 `.verified.jsonl` 仍是复用/验收证据；缺少对应 `.part` 不能直接判为多余。首版日志可能没有 `.v1` 后缀，对应已保留的 `.v1` 媒体，需结合合法版本链识别。
- 检查“下载目录”不能只选 `groups`：当前本机结构还包含 `downloaded` 根层、整个 `downloading` 下的 `partials` 和散落文件。全部检查应纳入已从配置移除但仍有下载目录的群；旧复用池、归档和浏览器会话按用户明确范围排除。
- 服务器分页未覆盖本地涉及范围、分页重复或本地文件发生并发变化时，保持检查失败，不能以未查到推断群里已删除。数字开头的原文 TXT 应结合内容文件路径记录识别，避免误当 TXT 附件。
